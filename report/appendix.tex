\subsection{RISC-V 目标架构与执行环境}
\label{app:riscv-environment}
选择 RISC-V 是因为 Ubuntu 提供配套交叉编译器、glibc 和 QEMU 用户态发行包，可以保持 ISA、目标文件和浮点 ABI 一致，无需构建大型编译器源码。实验目标为 RV64GC 与 LP64D，并生成 Linux ELF64 RISC-V 程序。LP64D 中整数与指针宽度不同：本实验 SysY 的 \texttt{int} 为 32 位，地址为 64 位，浮点参数使用硬浮点约定\cite{riscvabi}。

SysY 源程序由 Clang 14 交叉编译为 RISC-V Linux 目标，并以 RV64GC 指定指令集、LP64D 指定 ABI；完整构建命令见第三章。LLVM IR 使用 \texttt{llvm-as-14}、\texttt{opt-14} 与 \texttt{llc-14} 验证并生成目标文件，手写汇编由 \texttt{riscv64-linux-gnu-gcc} 汇编。统一选用带 \texttt{-14} 后缀的 LLVM 工具，是为了让 typed-pointer IR 与工具主版本相匹配，避免不同版本间的 IR 语法兼容差异。

生成的静态 RISC-V ELF 程序由 \texttt{qemu-riscv64} 用户态模拟器执行。该测试用于验证 RISC-V 指令及 Linux ABI 下的功能和输入输出行为；它不能代表真实硬件性能，报告也不从静态文件大小或指令数量推断执行时间\cite{qemu}。
